# Правила разработки ступени 4

- Это чистый сервисный шаблон R4. Требования, Changes и tasks принадлежат Store
  `sdd-credit-calculator-product-meta`; код, runtime-тесты и сборка — этому
  checkout.
- В `openspec/` допустим только `config.yaml` с Store pointer. Не создавайте
  локальные `specs`, `changes`, archive, history или другую копию planning.
- Начинайте личную ветку от точного `SERVICE_SHA`, переданного организатором.
  Отдельно подтвердите точный принятый `PLANNING_SHA` соседнего personal meta.
- Пользователь должен явно назвать разрешённые service и meta roots. Текущая
  сессия должна иметь доступ к обоим и прочитать `AGENTS.md` в каждом. Store
  pointer выбирает planning root, но не выдаёт доступ к файловой системе.
- OpenSpec-команды из сервиса выполняйте без `--store`. `list --json` и
  `status --change ... --json` должны показать `root.source = declared` и
  Store ID из config. При расхождении остановитесь: не регистрируйте Store
  заново и не меняйте глобальный `defaultStore`.
- До явного разрешения и завершения review принятого planning и сервисного
  состояния не запускайте Apply, не меняйте код/runtime-тесты и не закрывайте
  tasks.
- При разрешённой реализации изменяйте код и runtime-тесты здесь, а только
  фактически выполненные tasks — в personal meta. `.workspace` в meta всегда
  read-only и не является checkout для разработки.
- `.opencode/skills` содержит инструкции инструменту по работе с OpenSpec.
  Это не требования, не Change и не вторая копия планирования; не переносите туда
  продуктовый договор.
- `npm run check:code` проверяет автономное сервисное состояние и статический
  Store pointer. `npm run check:store` отдельно проверяет зарегистрированный
  Store; полный локальный gate — `npm run check`.
- Не сбрасывайте чужие изменения, не применяйте force и не сохраняйте секреты,
  персональные или рабочие корпоративные данные.
